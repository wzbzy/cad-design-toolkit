# 0002 - 相似性审计识别段从 pHash 聚类转向标签驱动视图组

## 状态

已接受（2026-10-14）

## 背景

相似性审计工具（spec #1）v1 的识别路线是"整图横向切块 → 渲染 → pHash 聚类"。真实一月订单（368 张 DWG）全量跑批后判定覆盖率 29.8%（不成立区间），但人工验收拆分包时发现该判定**不可信**：

- 切分器把俯视图整页、图框、附图当成"产品"——它根本不区分视图类型；
- 切分管线丢弃了全部 TEXT/MTEXT 文字，而探查证实真实图纸恰恰靠文字标注区分视图（"外观图/内部结构图/顶视图/左视图"）与柜型（"主卧衣柜""鞋柜"）；
- 图纸坐标远离原点（x≈2200 万 mm）、多柜视图组散排而非分带，v1 的横向切块假设全部落空。

## 决策

**识别段推倒重做，采用"标签驱动视图组"路线**：

1. **单元柜 = 视图组**：同一柜体的外观图/内部结构图/顶视图/侧视图贴同一文字标签成组，组即产品边界；JPG 取组内正视图（外观图），DXF 保留整组视图。
2. **文字优先、几何兜底**：柜型分类先用文字柜型词（订单号/柜名/尺寸标注同源），文字缺失时用高宽比与结构几何规则；文字图元不得丢弃。
3. **坐标先归一化**再谈任何网格/聚类。
4. **pHash 粗聚类退场**；相似度口径改为"同柜型内特征向量分档（拓扑全等 + 尺寸分箱）"。
5. **交付形态**：月度所有产品 jpg+dxf 平铺一个文件夹，命名 = 订单号-柜型-序号；无单号文件用原文件名 stem 兜底。
6. **85% 红线（图纸级）+ 30 张人工抽检双口径**；失败图占分母，ODA 转不动的坏文件单独归类。达不到 85% 时先向用户汇报差距与费用预估，拍板后才上 VL 视觉模型兜底（DeepSeek 官方 vision 实验模型已下线、由 V4.1-Flash 代答，兜底费用约 1 元量级，非门槛）。
7. **算法借鉴 ai-vision-cabinet-service**（文字提取、柜体启发式、尺寸规则），但不跨项目 import——审计工具保持可整体丢弃的独立性。

## 后果

- v1 的 families/ 聚类交付形态与 29.8% 判定作废；
- 转换适配器、渲染、报告骨架、测试基建（85 项）保留复用；
- 分类词表与图库标签词表对齐：移门衣柜/掩门衣柜/书柜/电视柜/鞋柜/玄关/书桌/梳妆台/橱柜/其他。
