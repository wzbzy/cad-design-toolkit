# MVP 计划（grilling 共识 checkpoint）

> 2026-10-14 与用户 grill 达成的设计树共识。改动本文件 = 改计划。

## 一期（MVP）范围

1. **插件**：AutoCAD .NET（C#，.NET Framework 4.7，一份二进制覆盖 AutoCAD 2018–2024），Plugin Bundle（.bundle + AutoLoader）分发，azerp 网页端下载页手动安装（拷入 `%APPDATA%\Autodesk\ApplicationPlugins`）
2. **登录**：复用 azerp `/sys/login` JWT（`X-Access-Token`），数据权限按门店自动隔离
3. **图库**：单表 `erp_cad_template` 挂 azerp `newerp` 模块（标签词表 + 文件 URL + `skp_url`/`product_ref` 两可空关联 + 宽/高/深 min-max 可调范围）；ERP 网页端维护（附图、文件路径、标签、备注）；存储位置由 ERP 配置，插件只认 URL
4. **检索**：插件内按标签/参数文字搜索（固定词表：柜型/门型/门数/风格/色系）
5. **插入**：动态块插入 + 拉伸调整（尺寸弹窗实时校验可调范围）；**图纸信息标准化**随插入落地——
   - 统一图框（带属性的块，图库/ERP 维护），字段值双存：图框属性（打印可见）+ 图纸数据字典（机器可读）
   - 两级信息模型：图纸级（客户名称/品牌/订单号，首次插入弹一次，同图不重复）+ 插入级（产品名称=模板名自动、门板型号/拉手/门铰/导轨，随尺寸弹窗默认继承上次值）
   - 必填最少化（图纸级仅客户名称），可空字段挂"待补清单"红点，交图前补齐；下拉数据源：客户=`/erp_customer/erpCustomer/listall`（现成，带门店数据权限）、产品名称=`erp_zkproduct/list`（现成）、品牌=`erp_logo`（现成）；拉手/门铰/导轨/门板型号=**新建轻量主数据表 `erp_cad_hardware`**（类别字典区分，Jeecg 代码生成器出 CRUD，未来 BOM 配方外键引用），全部本地缓存离线可用
   - 字段定义按 JSON schema 设计（label/必填/控件/数据源），插件动态渲染；v1 固定字段集，v1.x 上 ERP 配置界面
   - 插入级录入值直接进图纸台账 → 三期拆单五金清单 = 录入值 × BOM 配方
6. **规则引擎**（插件内 C#，JSON 可配置）：①板件尺寸约束校验（超限标红定位）②图层/颜色规范检查
7. **改造工具**（插件内一等模块）：程序做机械部分（图层清理、基点规整、尺寸提取、预打标签），人工（1 位 CAD 人员）做动态块定义与终审；首批从存量线条图中选约 200 个改造。**改造规范从第一批 30 个起包含「最简 BOM 配方」字段**（板件清单 = f(宽,高,深,变体) 的规则骨架），为拆单三期打数据地基

## 二期（显式推迟，黏性闭环：搜 → 插 → 查 → 下单全在 CAD 内）

- AI 按图搜索：效果图 → yzharness-ai 中台视觉模型按词表打标 → 标签匹配检索（中台需确认/补注册支持图片输入的模型）
- CAD 内嵌 ERP 下单页：插件 WPF 面板嵌 WebView2 加载 `/erp_ddcl/ErpDdclList_md` 创建生产订单，登录态复用插件 JWT 注入。azerp 新增订单表单的"下单方式"枚举已含 CAD（与酷家乐/EXCEL 并列），订单数据结构无需改动
- 订单 ↔ 图纸打通（表结构预留 product_ref）
- **三期·一键拆单**（产品终局：图纸生而可拆）：插入即写「图纸台账」（模板ID+参数+数量，存图纸自定义数据字典随 DWG 走）→ 服务端按 BOM 配方展开板件清单（XML/Excel）→ 喂给 azerp 部件/开料链路（erp_bjxx 已接收 guoji 开料数据、PanelElementsXmlConverter 已解析板件 XML，管道现成）。**不做几何识别**（行业坟场）：拆单数据从参数来，不从图上来；与 1010/筑木是喂料关系，不是替代
- 向量检索精排、独立安装器

## 显式不做

酷家乐集成、多 CAD 平台（中望/浩辰）、支付、独立账号体系

## MVP 验收标准（6 条，AI 搜索已移出）

1. 门店用 ERP 账号在 AutoCAD 2018+ 登录插件（JWT）
2. ERP 端新增模板（DWG+标签+预览图）后，插件可检索到
3. 插件按参数筛选 → 选中插入 → 拉伸调整尺寸
4. 规则①拉伸超板件尺寸上限标红定位；②图层/颜色不规范列出清单
5. 门店除安装插件外无需装任何其他软件
6. 模板本地缓存，断网可插入已缓存模板

## 预尸检（失败模式与对策）

| # | 死法 | 对策 |
|---|---|---|
| 1 | 图库没人维护/标签乱打 → 搜不到 → 不信任 | 标签词表下拉强制选择；上架审核；搜索无结果埋点 |
| 2 | 200 个改造做不完/质量差 | 先改 30 个验证规范再批量；改造工具机械部分自动化到位 |
| 3 | 设计师不换习惯 | 差异化卖点=「厂库同源、插入即可生产」+ 种子门店共创 |
| 4 | 门店 AutoCAD 环境老旧/破解，.bundle 加载失败 | **破解版不影响**（仍完整支持 .NET API/AutoLoader）；真正变量是版本：装机前摸底门店版本分布，若大量 <2018 则增加 .NET 4.0 目标（2013/2014）多编译一份；NETLOAD 手动加载作后备；验收第 1 条在真实门店机器实测 |
| 5 | azerp 变动弄坏插件 / ERP 团队排不上期 | 插件仅依赖少量稳定 API；接口契约文档化 |
| 6 | 门店断网/网络差 | 本地缓存 + 离线插入（已纳入验收 6） |
| 7 | 二期视觉打标不准 | 词表约束 + 置信度展示 + 内部评测先行 |
| 8 | 二期内嵌 WebView2 在老旧系统不可用（Win7 无 WebView2） | 摸底门店 OS 分布；降级方案为调起系统浏览器并带一次性 token |
| 9 | 强制输入惹恼设计师，宁可不插模板 | 必填最少化（图纸级仅客户名）；插入级默认继承上次值（看一眼点确认）；可空字段"待补清单"交图前补齐 |
